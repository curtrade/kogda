# Рабочий процесс с Claude Code: цикл К-О-Г-Д-А

Так я работаю с агентом с 1 октября 2026 года во всех проектах. Пять принципов:

| Буква | Принцип | Что это значит |
|---|---|---|
| **К** | Контекст | Агент получает правила проекта, нужный код и документацию, и ничего лишнего |
| **О** | Ограничения | Границы задачи заданы заранее: стек, стиль, что трогать нельзя |
| **Г** | Гипотеза | Спецификация: что должно получиться и как это проверить |
| **Д** | Дифф | Черновик агента я ревьюю сам, прежде чем он попадёт в историю |
| **А** | Автотесты | Линт, типы, тесты (unit, integration, e2e), сборка |

«Д» и «А» настроены глобально в `~/.claude/settings.json` и работают в любом проекте,
в том числе новом. «К», «О» и «Г» — это дисциплина и инструменты, которые я включаю сам.

## Как выглядит одна задача

```text
К  Контекст      CLAUDE.md, скиллы, /clear между задачами
О  Ограничения   deny-правила, раздел «Вне задачи» в спецификации
Г  Гипотеза      спецификация → план (superpowers или plan mode)
   │
   ├─ агент пишет код в auto-режиме, не спрашивая
   │    └─ конец каждого хода: быстрые проверки по его файлам (Stop-хук)
   │         красное → агент чинит сам, ход не заканчивается
   │
Д  Дифф          агент дошёл до git commit → запрос мне → смотрю /diff
   │               Yes — коммит; Esc + замечание — агент переделывает
   │
А  Автотесты     перед слиянием ветки — полный прогон руками: весь tsc, все тесты, e2e, сборка
```

Главное правило размера: **одна задача плана = один коммит = один дифф, который читается
за 5–10 минут.** Если дифф не читается, задача в плане была слишком крупной.

## К — Контекст

- Проектный `CLAUDE.md` должен быть коротким: команды, архитектура, запреты. Длинный файл модель
  читает вполглаза. Если правило не соблюдается, файл надо сократить или превратить правило
  в хук.
- Повторяющиеся процедуры оформлять скиллами, ресёрч делать через Tavily MCP.
- `/clear` между несвязанными задачами. Если поправил агента дважды по одному поводу, а он
  всё ещё ошибается, `/clear` и новый промпт с учётом того, что выяснилось.
- Разведку большой кодовой базы отдавать субагентам (Explore), чтобы она не забивала основной
  контекст. Сколько контекста занято, показывает `/context`.

## О — Ограничения

- **Жёсткие** задаются правилами `permissions.deny` в settings. Они действуют в любом режиме,
  например `"deny": ["Bash(git push *)"]`.
- **Мягкие** — правила в `CLAUDE.md` и фразы в чате («не трогай миграции»). Auto-режим
  соблюдает сказанное в чате, но после сжатия контекста фраза может потеряться, поэтому
  для важного нужен `deny`.
- В каждой спецификации есть раздел «Вне задачи».

## Г — Гипотеза

- Большая задача идёт через superpowers: `brainstorming` → спецификация в
  `docs/superpowers/specs/` → `writing-plans` → план в `docs/superpowers/plans/` →
  `subagent-driven-development`.
- Маленькая задача — через plan mode: `Shift+Tab` или `/plan <задача>`. `Ctrl+G` открывает
  план в редакторе, его можно поправить до старта. Если дифф описывается одним предложением,
  план не нужен.
- Хорошая спецификация называет файлы и интерфейсы, перечисляет, что вне задачи, и заканчивается
  проверкой, которая доказывает, что всё работает целиком.

## Д — Дифф

### Что настроено

В `~/.claude/settings.json`:

```json
"permissions": {
  "ask": ["Bash(git commit *)", "Bash(git * commit *)"]
}
```

Агент в auto-режиме правит файлы и запускает команды без вопросов, но **любой коммит
останавливается и ждёт меня**. Правило ловит и `git commit …`, и `git -C <путь> commit …`.
Фоновые субагенты (superpowers коммитит после каждой задачи плана) показывают запрос в основной
сессии и пишут своё имя. Проверено 1 октября 2026: свежая сессия в auto-режиме закоммитить
без разрешения не смогла.

Правило ловит команду в том виде, в каком её пишет агент. Это ворота для ревью, а не защита:
коммит изнутри скрипта оно не остановит.

### Как ревьюить

1. Появился запрос на `git commit`. Сразу «Yes» не нажимать.
2. Открыть дифф. В полноэкранном режиме (`"tui": "fullscreen"` уже стоит) при ширине терминала
   от 110 колонок `/diff` открывает панель рядом с диалогом, и она обновляется, пока агент
   работает. Если панель уже открывалась хоть раз, в следующих сессиях она открывается сама
   при первой правке.
3. В панели:
   - **Ctrl+X B** переключает базу сравнения: правки этой сессии → все незакоммиченные →
     вся ветка от main. Последний вариант нужен для ревью перед слиянием.
   - **Тесты и сгенерированные файлы панель прячет.** Внизу списка есть строка со счётчиком,
     её нужно развернуть. Тесты смотреть обязательно: агент чаще всего хитрит именно там.
   - **Замечание к строкам**: выделить их мышью, они прикрепятся к следующему промпту.
   - Правки, которые агент сделал через Bash (`sed`, `mv`), видны только в общем диффе,
     во вкладках по ходам их нет.
4. Решение:
   - **Yes** (разовое) — коммит проходит.
   - **Esc** и написать, что не так, — агент переделывает и снова просит коммит.
   - Принять часть: сказать агенту, какие куски убрать, или самому в соседнем терминале
     `git add -p` и `git commit`.
   - Откатить неудачный ход целиком: `Esc Esc` → Restore code. Откатываются только правки,
     сделанные инструментами редактирования; изменения через Bash остаются.

### Что искать в диффе агента

- Файлы вне задачи: сверить `git diff --stat` с планом.
- Ослабленные тесты: удалённые проверки, `.skip`, `.only`, мок того самого, что тестируется,
  ожидание, подогнанное под баг.
- Подавление ошибок: `eslint-disable`, `@ts-ignore`, `as any`, пустой `catch`, значение
  по умолчанию, которое прячет сбой.
- Новые зависимости и правки конфигов.
- Код, который дублирует уже существующую утилиту.
- Соответствие спецификации из «Гипотезы».

### Ревью агентом до моего (по желанию)

`/code-review` смотрит дифф в свежем субагенте и находит баги. Ревьюер, которого попросили
искать проблемы, найдёт их всегда, поэтому просить «только корректность и требования
спецификации». Последнее слово остаётся за мной.

## А — Автотесты

### Уровень 1: автоматически в конце каждого хода

Stop-хук запускается, только если агент **в этом ходу** правил файлы. Проверяются файлы,
которые агент изменил за сессию и которые ещё не закоммичены. Мои собственные незакоммиченные
правки хук не трогает.

| Проверка | Когда запускается | Что считается ошибкой |
|---|---|---|
| `tsc --noEmit` | изменены `.ts`/`.tsx`, есть `tsconfig.json` и `node_modules/.bin/tsc` | ошибки типов **в изменённых файлах**; старые ошибки в других файлах не мешают |
| `eslint <файлы>` | изменены JS/TS, есть `node_modules/.bin/eslint` | ошибки (предупреждения не мешают) |
| `vitest related --run` | изменены JS/TS, есть `node_modules/.bin/vitest` | красные тесты, которые импортируют изменённые файлы |
| `pytest -q` | изменены `.py`; скрипт `test:py` в `package.json` или `.venv`/`venv` с pytest | красные тесты; код 5 (тестов нет) не ошибка |

Проверки запускаются в ближайшей к файлу папке с `package.json`. Так работает и Крымея,
где корень git — `your-crimea`, а проект — `your-crimea/krymania`.

**Если красное**, агент не может закончить ход: он получает вывод и чинит. Если падение
не связано с его задачей (старая ошибка, нет базы, сломано окружение), он должен сказать
об этом и остановиться. Второй раз без новых правок хук ход не держит, а показывает мне
предупреждение «проверки остались красными».

**Если сам инструмент не отработал** (tsc упал, таймаут), ход не блокируется, а я вижу
предупреждение.

Сколько это занимает: sos — 2 с, Крымея — 10–15 с на ход с правками кода.

### Уровень 2: руками перед слиянием ветки

Хук ловит только то, что относится к правкам агента. **Он пропускает:**

- ошибки типов в файлах, которые агент не трогал, но сломал через импорт;
- e2e (Playwright) и сборку;
- правки, сделанные через Bash: они не попадают в учёт.

Поэтому перед слиянием ветки — полный прогон: весь `tsc`, все тесты, e2e, `build`.

### Свои проверки для проекта

Если автоопределение не подходит, положить в корень репозитория `.claude/kogda-checks.sh`.
Он заменяет автоопределение целиком, получает изменённые файлы аргументами (пути от корня
репозитория), а ненулевой код выхода означает «красное».

```bash
#!/bin/bash
# .claude/kogda-checks.sh — пример: только линт изменённых файлов, без тестов
cd krymania || exit 0
files=(); for f in "$@"; do [[ $f == krymania/*.ts* ]] && files+=("${f#krymania/}"); done
[ ${#files[@]} -eq 0 ] || pnpm exec eslint --no-warn-ignored "${files[@]}"
```

Отключить проверки в одном проекте можно файлом `.claude/kogda-checks.sh` с одной строкой `exit 0`.

## Где что лежит

| Путь | Что там |
|---|---|
| `~/.claude/settings.json` | `permissions.ask` (ворота на коммит), `hooks.PostToolUse` и `hooks.Stop` |
| `~/.claude/hooks/kogda/mark-edit.mjs` | после каждой правки агента запоминает файл |
| `~/.claude/hooks/kogda/gate.mjs` | в конце хода прогоняет проверки и держит ход, пока они красные |
| `~/.claude/hooks/kogda/lib.mjs` | общая логика: учёт, поиск проверок, запуск |
| `~/.claude/hooks/kogda/test/` | 23 теста на `node:test`: `npm test`, `npm run lint` в папке хуков |
| `~/.cache/claude-kogda/<сессия>/` | учёт правок по сессиям; папки старше 30 дней удаляются сами |

## Выключить и откатить

- **Один запуск без хуков:** `claude --settings '{"disableAllHooks": true}'`. Учти, что это
  выключит и хуки плагинов, например стартовый хук superpowers.
- **Один проект без проверок:** `.claude/kogda-checks.sh` с `exit 0`.
- **Совсем:** удалить из `~/.claude/settings.json` ключи `permissions.ask` и `hooks`.
- Посмотреть, какие хуки сейчас действуют и откуда: `/hooks`.

## Если что-то не так

- **Ворота или хуки не сработали.** Новые настройки надёжно подхватываются при старте сессии,
  поэтому перезапусти `claude`. В сессии, где я всё настраивал, хук учёта правок заработал
  сразу, а правило на коммит — нет.
- **Хук держит ход на старой ошибке.** Агент должен сказать, что ошибка не его. Второй раз
  без новых правок хук ход не держит.
- **Скрипты с `claude -p`.** Фабрика контента запускает `claude` с `--safe-mode`, хуки
  туда не попадают. Лид-машина запускает без него, но она сейчас отключена. Если её включать,
  сначала добавить `--safe-mode` и в неё.
