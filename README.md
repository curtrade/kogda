# К-О-Г-Д-А: как я веду разработку с Claude Code

ИИ-агент пишет код быстро. Отвечаю за этот код я. Здесь лежит то, чем я держу агента в рамках:
пять шагов работы, два хука и правила, которые получает каждая сессия.

| Буква | Шаг | Кто делает |
|---|---|---|
| **К** | Контекст: правила проекта, нужный код и документация, ничего лишнего | я |
| **О** | Ограничения: что трогать нельзя и что вне задачи | я |
| **Г** | Гипотеза: спецификация и план до первой строки кода | агент пишет, я утверждаю |
| **Д** | Дифф: черновик агента проходит моё ревью перед коммитом | я |
| **А** | Автотесты: типы, линтер и тесты по изменённым файлам | хук |

Подробное описание процесса — в [docs/workflow.md](docs/workflow.md).

## Зачем это нужно

Без рамок агент ошибается одними и теми же способами:

- делает проверки зелёными, ослабляя их: удаляет тест, ставит `.skip` или `as any`;
- чинит то, о чём не просили, и дифф перестаёт читаться;
- говорит «готово», не запустив тесты;
- коммитит раньше, чем человек увидел изменения.

Просьбы в чате от этого не спасают: после сжатия контекста они теряются. Спасает то, что
исполняет не модель, а среда: правила доступа и хуки.

## Что в репозитории

| Путь | Что это |
|---|---|
| `hooks/mark-edit.mjs` | хук `PostToolUse`: записывает, какие файлы агент изменил в сессии |
| `hooks/gate.mjs` | хук `Stop`: в конце хода гоняет проверки по этим файлам и не даёт закончить ход, пока они красные |
| `hooks/lib.mjs` | учёт правок и запуск проверок |
| `hooks/test/` | 23 теста на встроенном `node:test` |
| `examples/settings.json` | подключение хуков и запрос подтверждения на `git commit` |
| `examples/CLAUDE.md` | глобальные правила для агента по пяти шагам |
| `examples/spec.md`, `examples/plan.md` | настоящие спецификация и план одной задачи |
| `docs/workflow.md` | как строится работа над задачей от контекста до слияния |

## Как работают ворота

**Дифф.** Правило `permissions.ask` на `git commit` останавливает агента перед каждым коммитом.
К этому моменту он обязан написать, что сделал, какие файлы изменил и что поменялось в тестах.
Я смотрю дифф и либо подтверждаю, либо возвращаю с замечанием.

**Автотесты.** Хук `Stop` берёт только те файлы, которые агент менял в этом ходу, находит
ближайший к ним `package.json` и запускает там:

- `tsc --noEmit`, если есть `tsconfig.json`;
- `eslint` по изменённым файлам;
- `vitest related` по изменённым файлам;
- `pytest` для файлов на Python.

Если что-то красное, ход не заканчивается: агент получает вывод проверок и чинит сам. Проекту
с особыми проверками достаточно положить скрипт `.claude/kogda-checks.sh` — тогда хук запустит
его вместо встроенного набора.

## Чего хук не ловит

- e2e-тесты и сборку: они слишком долгие для конца каждого хода;
- ошибки типов в файлах, которые агент сломал через импорт, но сам не открывал;
- правки, сделанные через Bash: они не попадают в учёт;
- логические ошибки, на которые нет теста.

Поэтому перед слиянием ветки я делаю полный прогон руками: весь `tsc`, все тесты, e2e, сборка.

## Установка

Нужны Node.js 20 или новее и Claude Code.

```bash
git clone https://github.com/curtrade/kogda.git
cd kogda/hooks && npm ci && npm test
```

Затем перенесите блоки из [examples/settings.json](examples/settings.json) в свой
`~/.claude/settings.json`, заменив `/ПУТЬ/К/kogda` на путь к папке, и возьмите за основу
[examples/CLAUDE.md](examples/CLAUDE.md).

## Что это дало

- Два проекта в проде на Next.js 16, Payload CMS и PostgreSQL сделаны в одиночку за полгода.
  В них 1 600+ автотестов.
- Одна задача плана — один коммит — один дифф, который читается за 5–10 минут.
- Замер токенов показал, что вызов `claude -p` из скрипта тянул 14 840 токенов контекста
  вместо 546. Флаги `--safe-mode --tools ''` снизили стоимость вызова в 36 раз.
